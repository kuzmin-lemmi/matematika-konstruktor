# Конструктор материалов «Матшага»

Главная задача — облегчить работу ИИ-агента над материалами сайта. Автор задаёт тему и проверяет
готовый урок; ИИ использует общее ядро, шаблон темы, примеры и команды. Развитие конструктора должно
уменьшать объём повторяемого кода, неоднозначность инструкций и ручное вмешательство автора.
Обязательные правила — в `AGENTS.md`, рабочий маршрут создания темы — в `.claude/skills/novyi-material/SKILL.md`,
приоритеты инструмента — в `ПЛАН-ДОРАБОТКИ.md`. Здесь описаны фактические API и команды.

Конструктор собирает материал для сайта matshag.ru из двух частей:

- **ядро** (`core/`) — всё, что одинаково во всех материалах: стартовый экран, доска с шагами «вопрос → показ»,
  раздатка с кодовым словом и бланком ОГЭ, ключ по номеру варианта, печать A4, тренажёр с очками, подсказками
  и итогами «Над чем поработать», тёмная тема, ссылка для учеников;
- **тема** (`materials/<slug>/`) — только содержание: какие задания, как их проверять и объяснять ошибки,
  шаги показа на доске, справка.

Сборка склеивает их в **один самодостаточный HTML-файл** и кладёт его в сайт: `public/materials/<slug>.html`.
Для учителя ничего не меняется — тот же файл, работает с флешки, адреса страниц прежние.

ИИ пишет содержание темы и переиспользует каркас. Объём темы зависит от математики и взаимодействий;
количество строк не является критерием качества. Улучшение ядра получают все темы после пересборки.

## 1. Подготовка (один раз)

На компьютере должны быть:

- **Node.js** версии, совместимой с `engines` обоих `package.json` (для сайта — `^22.13.0 || >=24.0.0`);
- **git**; для команды `publish` — **GitHub CLI** (`gh`) с выполненным входом: проверь `gh auth status`;
- **папка сайта** — клон github.com/kuzmin-lemmi/matematika; путь на этом компьютере — в `constructor.config.local.json`.
  Для `publish` нужен заранее обновлённый `main`, пустой индекс и изменения только выбранной темы.
  Разработка и `check` возможны в рабочей ветке.

В папке конструктора один раз:

```bash
cd "<папка конструктора>"
npm ci
```

Путь определяется в порядке: `--site`, `MATSHAG_SITE`, `constructor.config.local.json`,
`constructor.config.json`, папка `../matematika`. Для другого компьютера используй локальный конфиг:

```json
{ "site": "F:/matematika" }
```

На один запуск — флаг `--site <папка сайта>`. Локальный конфиг исключён из git;
машинный путь в общем конфиге не меняй ради настройки своего компьютера.

### На другом компьютере

Конструктор лежит на GitHub: **github.com/kuzmin-lemmi/matematika-konstruktor**, сайт —
**github.com/kuzmin-lemmi/matematika**. Чтобы работать на новом компьютере:

1. Поставь **Node.js 22.13+**, **Git** и **GitHub CLI** (cli.github.com), затем войди в GitHub:

   ```bash
   gh auth login
   ```

2. Склонируй оба репозитория **в одну папку** — тогда конструктор сам найдёт сайт рядом:

   ```bash
   git clone https://github.com/kuzmin-lemmi/matematika
   git clone https://github.com/kuzmin-lemmi/matematika-konstruktor
   cd matematika
   npm ci
   cd ../matematika-konstruktor
   npm ci
   ```

   Если сайт лежит в другом месте — создай в папке конструктора файл `constructor.config.local.json`
   (в git он не попадает): `{ "site": "C:/путь/к/matematika" }`.

3. Проверь, что всё работает: `npm test` в папке конструктора.
4. Открой папку конструктора в чате с ИИ — дальше как в разделе 2.

**Работа с двух компьютеров.** На каждом — одна папка конструктора и одна папка сайта, источник правды — GitHub.
Начал работу — подтяни обе папки; закончил — всё на GitHub (`git push`), незаконченное — в отдельной ветке.
Две копии сайта на одном компьютере не держи: конструктор пишет в одну, а правишь другую.

Перед обновлением проверь `git status -sb` в обеих папках и разбери существующие изменения.
Обновление выполняется отдельно: `git pull --ff-only` в нужной ветке каждого репозитория.
`check` не обновляет Git; `publish` синхронизирует `main` только после слияния своего PR.
Изменения конструктора отправляй отдельным `git push`, иначе на другом компьютере их не будет.

Доступ к папкам и командам зависит от среды агента. Проверяй его на текущем компьютере;
не считай сохранённую настройку другого компьютера подтверждением доступа.

## 2. Как сделать новый материал

### Через чат с ИИ — основной путь

Подходит любой ИИ-агент, который работает с папками и командной строкой: Claude Code (приложение Claude,
вкладка Code, или терминал), Codex, opencode, Gemini CLI, Cursor, Zed и другие. Правила для всех лежат в папке
конструктора: `AGENTS.md` (Codex, opencode, Cursor, Zed), `CLAUDE.md`, `GEMINI.md`,
`.github/copilot-instructions.md` — агент прочитает их сам.

1. **Открой новый чат и выбери папку конструктора** (на работе `D:/Конструктор математика`, дома
   `F:/конструктор математика`). Агенту нужен доступ и к папке сайта из `constructor.config.local.json`:
   туда кладутся материал, карточка и тест.
2. **Напиши, что нужно.** Например:

   > Сделай материал «Свойства арифметического квадратного корня», 8 класс, Макарычев: корень из произведения
   > и дроби, вынесение и внесение множителя. Все три режима и бланк ОГЭ.

   Можно добавить, что важно: какие ловушки показать на доске, сколько заданий в раздатке, для какого урока.
3. **ИИ делает материал**: заготовку (`npm run new`), тему, тест, карточку, постер, затем прогоняет
   `npm run check` — все проверки конструктора и сайта.
4. **ИИ показывает материал**: `npm run show` открывает его в браузере, в чате — что сделано по режимам.
   Посмотри: пройди шаги доски, открой все доступные виды раздатки и предпросмотр печати (Ctrl+P), реши пару заданий
   в тренажёре и ошибись нарочно.
5. **Ответь:**
   - нужны правки — напиши какие, ИИ исправит и покажет снова;
   - всё хорошо — напиши **«одобряю, публикуй»**.
6. **ИИ готовит актуальный `main` сайта отдельно**, затем запускает `npm run publish -- <slug> --approved`:
   сборка выбранной темы, проверки, коммит, PR, слияние, GitHub Pages, проверка matshag.ru,
   первый снимок вариантов при его отсутствии. В конце пришлёт ссылку
   `https://matshag.ru/item/<slug>/`.

Без твоего «одобряю» команда публикации не запустится: без флага `--approved` она отказывает, а правила
запрещают ИИ ставить флаг без явного одобрения в чате.

Отправка исходников на GitHub не равнозначна одобрению публикации конкретного материала.
Ограничения среды агент проверяет отдельно, не обещая заранее настроенную авторизацию.

### Вручную, по шагам

1. **Заготовка:** `npm run new -- slozhenie-drobei --title "Сложение дробей с разными знаменателями"`.
   slug — транслит латиницей через дефис; после публикации не меняется (на него ведут раздатки и ссылки в чатах).
   Команда создаст тему `materials/<slug>/` с рабочим примером, на сайте — карточку (`access: soon`)
   и черновик теста `tests/<slug>.test.mjs`, и соберёт файл материала.
2. **Наполнить тему** — заменить всё с пометкой «ЗАМЕНИ» (раздел 3 ниже).
3. **На сайте:** дописать в тесте независимое решение; в карточке — `access: free`, `added`, `poster`,
   описание по абзацу на режим, `sheets` для бланка ОГЭ.
4. **Проверить:** `npm run check -- <slug>`. **Посмотреть:** `npm run show -- <slug>`.
5. **Опубликовать:** `npm run publish -- <slug> --approved`.

## 3. Из чего состоит тема

```
materials/<slug>/
  material.json   тексты страницы: название, описание, подписи режимов, заголовки
  topic.js        содержание: параметры, типы заданий, разделы тренажёра, раздатка, доска
  help.html       справка в тренажёре (формулировки как в учебнике)
  topic.css       необязательно: стили, нужные только этой теме
```

### material.json

| Поле | Что это |
|---|---|
| `title` | название темы — заголовок страницы и листов |
| `description` | описание для поисковиков и превью ссылки |
| `kicker` | строка над заголовком: «8 класс · Макарычев и др. · Алгебра» |
| `lead` | подзаголовок стартового экрана |
| `modeBoard`, `modePrint`, `modeHome` | тексты карточек режимов на стартовом экране |
| `printTitle`, `homeTitle` | заголовки раздатки и тренажёра |
| `homeIntro` | текст над выбором раздела в тренажёре |

### topic.js — что тема обязана объявить

Сборка проверяет, что всё это есть, и не соберёт тему без них.

| Объявление | Что это |
|---|---|
| `const CONFIG` | параметры, которые учитель может поменять: `board.previewDelay`, `print.{variants, traps, space}`, `home.{round, points[], hintPenalty, maxMultiplier}` и свои |
| `const GEN_VERSION` | версия генератора — первая часть номера варианта «1-4817» |
| `const TYPES` | типы заданий (ниже) |
| `const CATS` | типы ошибок для «Над чем поработать»: `{ код: [название, совет] }` |
| `const SECTIONS` | разделы тренажёра: `{ title, text, types: [...], ex() }`; `ex()` — пример задания формулой; если пример словами, добавь `exText: true` — он будет мельче названия раздела |
| `const KINDS_V1` | состав варианта раздатки: `[тип]`, `[тип, форма]` или `[тип, [формы]]` |
| `const WORDS_V1` | слова для кодового слова: столько букв, сколько заданий, буквы не повторяются |
| `const PRINT` | тексты листа: `instr` (ученику), `about` и `ogeAbout` (учителю под кнопками печати) |
| `function boardExample(random, old)` | пример для доски: `false` — из `CONFIG.board`, `true` — «Другие числа» |
| `function buildSteps(e)` | шаги доски для примера `e` |
| `const BOARD` | `{ previewUntil, poster }` — до какого шага крутится превью и какой шаг снимать на картинку |

Необязательно:

| Объявление | Что это |
|---|---|
| `const OGE_V1` + `function ogeTask(kind, rnd)` | бланк ответов как в ОГЭ: состав и задание `{ kind, t, ask, ans }`, `ans` — число строкой |
| `const LIVE` + `live` на шагах | живая доска: модель, ручки, панель, опыт — раздел 9 |
| `function helpInit()` | дорисовать формулы в справке (дроби, корни) |
| `const TOPIC_INPUTS` | свой вид ввода ответа: `{ имя: { html(t), collect(get) } }` |
| `const TOPIC_SHEETS` | дополнительные виды листов: реестр по `kind`, см. раздел 9 |
| `const TOPIC_PRINT_VERSIONS` | генераторы по версии и `kind`; ограничения снимков — раздел 9 |

### Тип задания

```js
sum: {
  input: 'num',                    // num | frac | choice | eq | est | свой из TOPIC_INPUTS
  gen: (rnd, form) => ({ ... }),   // задание из зерна — никакого Math.random()
  bad: t => ...,                   // вырожденные случаи: true — сгенерировать заново
  text: t => '...',                // запись задания (HTML)
  ans: t => Q(...),                // ответ: число {n, d} для num/frac, строка для choice
  ok: t => '...',                  // короткое объяснение верного ответа
  wrong: (t, x) => bad('код', '...'),  // объяснение ошибки с вычислением; типичная — по имени
  hints: t => ['...', '...'],      // две подсказки: общая и почти ответ
  traps: t => [{ key, html }],     // ответы-ловушки для таблицы букв — на типичных ошибках
  // необязательно: options (для choice), key/keyHTML (запись ответа в ключе),
  // ask (вопрос в тренажёре), sheet (формулировка на листе), answer (ответ в разборе ошибки), same
}
```

Готовые функции ядра: случайные `int`, `pick`, `shuffle`, `mulberry32`; точные дроби `Q`, `qadd`, `qsub`,
`qmul`, `qeq`, `qneg`, `gcd`, `isqrt`, `qsqrt`, `floorSqrt`, `toMixed`, `decStr`; запись `F` (дробь этажом),
`M` (смешанное число), `RT` (корень), `X` (курсивный x), `htmlQ`, `keyQ`, `esc`, `plural`, `MINUS`;
чертежи `tx`, `grid`, `under`, `svgFrac`, `numLine`, `sr`, `ds`; геометрия — объект `GEO`, живая доска — `LIVE`
и `liveTo` (раздел 9). Пример записи и чисел — тема `materials/arifmeticheskii-kvadratnyi-koren/`,
пример живой доски — заготовка `templates/new-material/topic.js`.

## 4. Проверки

`npm test` в конструкторе — **тест-контракт** для каждой темы:

- открывается во всех режимах без ошибок, ссылка «Назад на сайт», ссылка для учеников — только тренажёр;
- тема описана полностью: у каждого типа есть генератор, проверка, объяснение, подсказки;
- раздатка: 30 вариантов различны, номер восстанавливает вариант, буквы ключа складываются в слово;
- бланк ОГЭ (если есть): ответы — числа, которые помещаются в клеточки;
- доска: все шаги вперёд и назад на 15 разных примерах, кадр для превью;
- живая доска (шаги с `live`): ручки в крайних положениях и стрелками, крайние значения панели —
  модель допустима, ручки внутри чертежа, «Сбросить» и «Повторить опыт» возвращают шаг;
- тот же контракт проходит заготовка `templates/new-material` — `npm run new` даёт рабочий пример;
- тренажёр: в каждом разделе верные ответы принимаются, неверные объясняются с вычислением;
- работает без localStorage;
- **замороженные варианты**: если для темы есть снимок `tests/snapshots/<slug>.frozen.json`, собранный
  материал обязан давать ровно те же варианты раздатки.

Тест темы на сайте (`tests/<slug>.test.mjs`) проверяет главное, чего не может знать конструктор:
**ответы, посчитанные независимо** от кода материала.

## 5. Важные правила

- **Собранный файл руками не правим.** Вверху файла это написано. Правим тему или ядро и пересобираем.
- **Напечатанные листы должны давать прежние ответы.** Первый снимок, если его ещё нет:

  ```bash
  npm run snapshot -- <slug>
  ```

  `publish` создаёт первый снимок автоматически. Повторный `snapshot` перезаписывает файл —
  не запускай его поверх сохранённого снимка для исправления теста.
  Для новой версии нужны отдельные снимки, проверка старых номеров и изоляция старого генератора
  вместе с типами и константами. Автоматический обход снимков разных версий ещё не реализован (раздел 9).
- **Изменил ядро — пересобери все темы:** `npm run build -- --all`, затем `npm test` и проверки на сайте.
- Правила содержания материалов (математическая запись, методика, ловушки на типичных ошибках, печать) —
  в `AGENTS.md` сайта, разделы 5 и 7, и в `docs/FORMATS.md`, `docs/TECH.md` сайта.

## 7. Команды — коротко

| Команда | Что делает |
|---|---|
| `npm ci` | установить зависимости по lock-файлу отдельно в каждом репозитории |
| `npm run new -- <slug> --title "Название"` | заготовка новой темы, карточки и теста на сайте |
| `npm run build -- <slug>` | собрать тему в сайт (`--all` — все темы, `--site <папка>` — другой сайт) |
| `npm test` | тест-контракт и замороженные варианты |
| `npm run check -- <slug>` | пересобрать выбранную тему, обновить постеры при необходимости, проверить карточку, запустить тесты конструктора и `validate` сайта; Git и зависимости не обновляет |
| `npm run show -- <slug>` | пересобрать выбранную тему и открыть её в браузере; не заменяет `check` |
| `npm run publish -- <slug> --approved` | опубликовать на matshag.ru — только после одобрения |
| `npm run snapshot -- <slug>` | записать снимок с перезаписью; использовать для первого снимка, существующий сохранять |

## 8. Если что-то пошло не так

- **Команда остановилась с «✗»** — в сообщении написано, что не так и что сделать (карточка не заполнена,
  тест не прошёл, в папке сайта чужие правки). Исправь и запусти снова; ИИ делает это сам.
- **«В папке сайта ветка … нужна main»** — сначала проверь статус и сохрани работу в её ветке,
  затем подготовь `main`. Не переноси чужие изменения переключением вслепую.
- **«незакоммиченные изменения не про материалы»** — в папке сайта кто-то правил код или правила; их нужно
  сохранить и отправить отдельным PR; публикация материала их не трогает. Не удаляй работу ради запуска команды.
- **Сайт показывает старую версию** — обнови страницу через пару минут: кэш браузера до 10 минут.
- **Нужно убрать материал с сайта или сменить адрес** — это решает только автор и делается отдельно, не командой
  publish (адреса уже могут быть в раздатках и чатах классов).

## 9. Расширения и границы текущей реализации

### Живая доска

Методические требования — в разделе «Живая интерактивная доска» AGENTS.md. Ядро (`core/live.js`)
берёт на себя управление: мышь, касание и перо (Pointer Events), стрелки клавиатуры на ручке,
панель под чертежом, «⟲ Сбросить», «▶ Повторить опыт», плавное движение, prefers-reduced-motion,
остановку движения, когда учитель листает. Тема пишет только математику. Рабочий пример —
заготовка `templates/new-material/topic.js` (числовая прямая: две ручки, ползунок, переключатель, опыт).

Модель — одна на доску, общая для всех шагов:

```js
const LIVE = {
  model: e => ({ a: e.a, b: e.b, go: 1 }),   // исходное состояние для примера e — простые данные: числа, строки, {x, y}, массивы
  fix(m) { m.a = Math.round(m.a); },         // необязательно: прилипание, границы — после каждого изменения
  ok: m => m.b !== 0,                        // необязательно: false — вырожденное положение, изменение откатывается
};
```

Шаг доски получает модель: `draw(phase, m)`, `rec(phase, m)`; `q`, `a`, `note` могут быть функциями `(m, phase)`.
Что можно делать на шаге — поле `live`:

| Поле | Что это |
|---|---|
| `enter(m)` | поставить модель при входе в шаг; `liveTo(...)` внутри — плавно |
| `reveal(m)` | опыт по «Показать ответ», обычно `liveTo({ go: 1 }, 1400)`; «▶ Повторить опыт» запускает его снова |
| `handles(m, phase)` | ручки на чертеже: `[{ id, at: {x, y}, label, move(m, p), key?(m, dx, dy, fine), keyStep?, r? }]`; `move` получает точку чертежа, уже ограниченную рамкой 980 × 400 |
| `controls(m, phase)` | панель под чертежом: `range` (`min, max, step, get, set, text?`), `toggle` (`get, set`), `choice` (`options: [[значение, подпись]]`, `get, set`), `button` (`run`); у любого — `disabled?(m)` |

`liveTo(цель, ms)` или `liveTo([цель1, цель2], ms)` плавно меняет числа модели, в том числе внутри `{x, y}`
и массивов. При reduced-motion и в тестах конечное положение ставится сразу. «Сбросить» возвращает
модель к началу шага (на показанном ответе — к итогу опыта); «← Назад» с ответа — к положению до опыта;
«↺ Заново» — к `LIVE.model(e)`. Стрелки на сфокусированной ручке двигают её (по умолчанию на 20 единиц,
с Shift — на 5) и не листают шаги. Если величина прилипает к шагу (углы через 5°), задай свой `key`.

Тест-контракт проверяет каждый шаг с `live` на обоих этапах (вопрос и ответ).
Ручки тянутся в углы, к краям и в центр чертежа, сдвигаются стрелками; элементы панели принимают
крайние значения. После этого модель должна остаться конечной и допустимой (`ok`), а ручки — внутри
чертежа. Ещё тест проверяет, что «Сбросить» и «Повторить» возвращают шаг в исходное состояние.
Для отладки: `APP.board.model`, `.handles`, `.controls`, `.drag(id, {x, y})`, `.key(id, dx, dy)`, `.set(id, v)`.

### Чертёжные помощники GEO

`core/geom.js` — объект `GEO`, доступный теме при загрузке. Его функции не пересекаются с именами темы;
нужные можно достать так: `const { pt, seg, vertex } = GEO`. Координаты — экранные (y вниз), углы — в градусах,
0° — вправо, 90° — вверх, положительный поворот — против часовой стрелки.

- Вычисления: `pt, add, sub, scale, len, dist, mid, lerp, unit, perp, polar(V, угол, r), dirDeg(V, P),
  angleAt(V, A, B)` (0…180°), `turn(P, C, угол), project, reflect, cross` (null у параллельных),
  `lineCircle, circles` (построения циркулем), `area, centroid, orient, bbox, snap, clamp, f1`.
- Контроль: `fine(точки, { side, angle })` — фигура не вырождена (для `LIVE.ok`), `inBox, keepIn`,
  `fit(точки, рамка, { pad, flipY })` — вписать модель в свои единицы, `clip(P, Q)` — прямая в рамке.
- Рисунок (строки SVG, классы `g-*` в base.css, подписи на подложке цвета фона): `seg, line` (через всю рамку),
  `ray, poly, path, circle, dot, text, vertex(P, 'A1', центр)` (подпись наружу, с индексом), `side(p, q, s, opp)`,
  `sector, arc, arcs` (дужки равенства), `right` (прямой угол), `ticks` (штрихи), `angleText` (величина на биссектрисе),
  `arrow, parallel, name`. Классы: `g-ln, g-thin, g-dash, g-hl, g-fig (.b, .ghost), g-circ, g-pt, g-mark, g-tick,
  g-sec (.a), g-arrow, g-vl, g-lab, g-num (.a, .b)`.

Сумма округлённых величин может отличаться от точной (59° + 61° + 61°): подписывай округлённые значения
так, чтобы вывод на доске оставался верным, например третью величину считай как 180° минус две другие.

### Дополнительные листы

TOPIC_SHEETS — объект, где ключ обозначает kind, например proofs или ticket.
Значение: { label, about, generate(num), sheet(variant, space), key(variants), two, previewKey, pageClass }.

- generate(num) возвращает воспроизводимую модель листа с label; sheet и key возвращают HTML.
- space сообщает, нужны ли поля для решения; two: false запрещает два варианта на листе.
- previewKey: true включает просмотр ключа на экране; pageClass добавляет класс обёртки печати.
- Ядро создаёт кнопки, читает ?kind, запоминает выбор и раскладывает листы.
- Подмена drawSheets и создание меню печати из helpInit запрещены. helpInit предназначен для справки;
  существующая панель модели Пифагора в нём — временная реализация до общего API доски.
- Образец: materials/priznaki-ravenstva-treugolnikov/topic.js. Снимки дополнительных форматов
  содержат модель и ключ. Новый формат требует собственного зафиксированного ожидания.

### Версии генераторов

TOPIC_PRINT_VERSIONS имеет вид { 1: { word: oldWord, ... }, 2: { word: newWord, ... } }.
В каждой версии перечисляются все доступные ей форматы. printVariant(n, kind, version)
выбирает генератор; явный номер вроде 1-4817 сохраняет версию при вводе и сохранении.
Генератор возвращает модель со своей подписью label.

Старые генераторы сохраняются вместе с типами, ответами, константами и способом отрисовки модели.
Ссылка старого генератора на изменённый TYPES не сохраняет совместимость. Старое зерно задаётся
явно: taskRnd(n, i, 1). При изменении модели обеспечь совместимые sheet/key.

Текущие инструменты снимков ещё не поддерживают каталог версий: snapshot перезаписывает
<slug>.frozen.json, а snapshot.test.mjs сравнивает его с текущей генерацией.
Поэтому повышение GEN_VERSION само по себе не является готовой миграцией. До выпуска версии 2
нужно реализовать отдельные файлы снимков версий и обход их тестом через printVariant(n, kind, version),
не перезаписывая старые ожидания. Дополнительные листы треугольников пока используют текущую
GEN_VERSION и требуют изоляции при такой миграции. См. этап 2 плана.

### Что именно отправляет publish

Только шесть файлов одной темы: public/materials/<slug>.html, src/content/items/<slug>.md,
tests/<slug>.test.mjs, public/posts/<slug>.jpg, public/posts/<slug>-dark.jpg,
public/posts/<slug>.source.json. Точный список — tools/publication-files.mjs.
Общие документы, код сайта и результаты общей правки ядра отправляются отдельным PR.
Команда не отправляет конструктор через git push; это отдельное завершающее действие агента.
