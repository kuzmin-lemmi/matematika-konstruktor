# Новый материал в конструкторе «Матшага»

Конструктор: `D:\Конструктор математика`. Сайт: путь в `constructor.config.json` (сейчас
`C:/Users/admin/Desktop/matematika`; если работаешь в worktree сайта — передавай `--site <папка worktree>`).
Пиши по-русски: ответы, комментарии, тексты интерфейса, коммиты.

## 0. Прочитай перед работой

1. `ИНСТРУКЦИЯ.md` конструктора — как устроена тема, что обязательно, команды.
2. Сайт: `AGENTS.md` (разделы 4, 5, 7, 8, 9), `docs/FORMATS.md`, `docs/TECH.md`,
   `docs/MATERIALS.md` — банк идей и **типичные ошибки учеников по теме** (из них строятся ловушки).
3. Образец готовой темы: `materials/arifmeticheskii-kvadratnyi-koren/` — как писать типы заданий, объяснения
   ошибок, шаги доски с SVG, бланк ОГЭ.

Не выдумывай номера параграфов и страницы учебника: в карточке — только название главы, в ответе скажи об этом.
Содержание учебника по главам сверяй у автора, если сомневаешься в объёме темы.

## 1. Заготовка

```bash
cd "D:\Конструктор математика"
npm run new -- <slug> --title "Название темы" [--site <папка сайта>]
```

slug — транслит латиницей через дефис; после публикации не меняется. Заготовка сразу собирается и проходит
тест-контракт — дальше заменяй пример своим содержанием, периодически собирая и проверяя.

## 2. Спроектируй до кода

- **Доска** — 8–12 шагов «вопрос классу → показ». Главная картинка темы (SVG, viewBox 980 × 400), шаг-ловушка
  на самой частой ошибке, шаг «а если условие нарушить», в конце — правило. `note` — что сказать словами.
  «Другие числа» (`boardExample(true, old)`) — тот же показ с новыми удобными числами.
- **Типы заданий** — 4–10. Генерация из зерна, отсев вырожденных случаев в `bad`: одинаковые варианты,
  ответ виден без вычислений, «случайно» целый ответ, где тренируется дробный.
- **Ошибки** — каждая объясняется с вычислением, типичная называется по имени («Ты сложил числители
  и знаменатели…»). Коды ошибок — в `CATS`.
- **Ловушки раздатки** (`traps`) — ответы, которые получаются при типичных ошибках, а не случайные числа.
- **Тренажёр** — 2–4 раздела по сложности или по видам заданий.
- **Раздатка** — 6–8 заданий, ответы в варианте различны; задание с выбором (2–3 ответа) — одно на вариант.
- **Бланк ОГЭ** (8–9 класс) — свои задания (`OGE_V1`, `ogeTask`) с ответом-числом: «в ответ запишите больший
  корень», «номер наибольшего числа». Ответ — строка вида `−0,5`, до 10 символов.

## 3. Наполни тему

`material.json` (тексты), `topic.js` (содержание), `help.html` (справка), при нужде `topic.css`.
Запись — функциями ядра: дробь `F`, смешанное число `M`, корень `RT` (дробь под корнем — `RT(..., true)`),
`htmlQ`/`keyQ`/`decStr` для чисел, `MINUS` (U+2212) для минуса, десятичная запятая. Точная арифметика —
дроби `Q` (никаких 0.1 + 0.2). Никакого `Math.random()` в `gen` — только `rnd` из аргумента.

```bash
npm run build -- <slug> [--site <папка сайта>]
npm test
```

## 4. Проверь глазами

- Доска: все шаги, обе темы (светлая и тёмная), элементы не выходят за viewBox, подписи не налезают.
- Раздатка: предпросмотр печати / PDF — лист A4 с сеткой, без сетки, **два варианта на листе** (низ не обрезан),
  ключ; бланк ОГЭ — клеточки и образец.
- Тренажёр на ширине телефона (390 px): поля ввода, кнопки, длинные формулы не рвутся.
- Снимки можно делать безголовым Chrome через CDP (как `scripts/capture-posters.mjs` сайта), если окно
  встроенного браузера не отрисовывается.

## 5. Сайтовая часть, показ, одобрение, публикация

Файлы сайта лежат в папке сайта (`constructor.config.json`); `npm run new` уже создал их черновики.

1. `tests/<slug>.test.mjs` — **независимое решение** каждого типа (ответ считает тест, не код материала):
   генератор, ключ 30 вариантов, тренажёр принимает независимый ответ, типичные ошибки называются.
   Для бланка ОГЭ — отдельная функция ответа.
2. Карточка `src/content/items/<slug>.md`: `access: free`, `added` (дата публикации), `poster: posts/<slug>.jpg`,
   `order` по классу, описание по абзацу на режим, `sheets: - { kind: oge, label: "Бланк ОГЭ" }` если есть бланк.
   Если в тот же день уже добавлен другой материал — `featured: true`, иначе в блоке «Новое» останется он.
3. `docs/ROADMAP.md` сайта — отметь задачу `[x]` с датой; решение автора — в журнал `docs/STRATEGY.md`.
4. **`npm run check -- <slug>`** — сборка, постер (снимет, если нет), карточка, тест-контракт, `npm run validate`
   сайта. Пока есть «✗» — исправляй.
5. **`npm run show -- <slug>`** — открыть материал автору. Напиши коротко: что на доске, в раздатке (оба вида листа),
   в тренажёре, что посмотреть руками (печать, телефон). **Спроси, публиковать ли.**
6. Публикуй **только после явного одобрения автора в чате** на этот материал («одобряю», «публикуй»,
   «отправляй на сайт»): **`npm run publish -- <slug> --approved`**. Команда сама: свежий main, сборка, проверки,
   ветка и коммит («Добавь материал «…» и его карточку»), PR, слияние, GitHub Pages, проверка matshag.ru,
   заморозка вариантов в конструкторе. Сообщи автору ссылку из итога.

Не публикуй вручную (git/gh в обход команды) и не ослабляй проверки, чтобы команда прошла.
Правки ядра и кода сайта — обычным PR в репозиторий сайта: `publish` коммитит только материалы.

## 6. Ловушки, на которые уже наступали

- **NaN/undefined в ключе или таблице букв** — у типа с нечисловым ответом (`est`, `choice`, `eq`) нет своего
  `keyHTML`/`key`. Тест-контракт ловит, но лучше сразу задать.
- **Обрезанный лист** при «два варианта на листе» — длинная инструкция или много ловушек; проверяй PDF.
- **Чертёж за краем** — координаты считай от viewBox 980 × 400 (так обрезалась прямая y = −9 на параболе).
- **Вёрстка рассыпается** в `.inrow` и карточках разделов (flex): несколько инлайн-кусков (`<i>x</i><sub>1</sub> =`)
  оборачивай в `<span class="nw">`.
- **Перенос посреди формулы** — `<span class="nw">…</span>` вокруг «x = ±√14», выражения с коэффициентом.
- **Минус дефисом** — в подписях SVG тоже нужен `MINUS`.
- **Сравнение в тестах jsdom** — массивы и объекты из окна материала — другой «мир» JS: сравнивай
  `[...arr]` или через `JSON.parse(JSON.stringify(x))`.
- **Совпадение заданий** бланка и кодового слова с одним номером возможно для небольших генераторов — это не ошибка.
- **Скрытая раздатка** — второй вид листа должен быть виден: в материале (кнопки на стартовом экране, переключатель)
  и на сайте (поле `sheets` карточки).
- **Изменились варианты опубликованной темы** — тест снимка упадёт. Не обновляй снимок, чтобы «починить тест»:
  либо верни генератор, либо подними `GEN_VERSION` по правилам `ИНСТРУКЦИЯ.md`.

## 7. Ядро

Правка `core/` касается всех тем: после неё `npm run build -- --all`, `npm test`, тесты сайта, проверка печати
и доски хотя бы у одной темы. Новая общая возможность (вид ввода, вид листа, помощник чертежа) — в ядро,
тематическое — в тему.

## Живая интерактивная доска — обязательное условие (решение автора от 2026-10-28)

При создании каждого нового материала ИИ обязан искать как можно больше содержательных способов
сделать объяснение интерактивным. Ориентир — материал «Накрест лежащие, соответственные и односторонние
углы, образованные при пересечении параллельных прямых секущей» (ugly-pri-parallelnyh-pryamyh).
Перед проектированием изучи его доску в папке сайта: движение секущей, изменение углов и подсветка связей.

До написания темы перечисли подходящие взаимодействия и математический смысл каждого: перетаскивание
точек и фигур, изменение параметров, поворот и наложение, разрезание и сборка, связанные представления,
подсветка соответствий, проверка гипотезы, контрпример при нарушении условия. Реализуй все полезные
для понимания темы взаимодействия, которые не перегружают урок; объясни, почему остальные не подходят.
Одна смена слайдов или кнопка «Другие числа» не заменяет живое исследование.

Ученик сначала предсказывает результат, учитель меняет модель, класс наблюдает и формулирует вывод.
Темп задаёт учитель; предусмотрены сброс, повтор опыта и возврат к исходному состоянию.
Математические зависимости сохраняются при движении, вырожденные случаи контролируются.
Управление работает мышью, касанием и клавиатурой; числа и чертёж читаются на проекторе.
Декоративная анимация не самоцель. При prefers-reduced-motion отключай лишнее движение, сохраняя
управление моделью. Проверь крайние положения и размеры экрана. В отчёте перечисли, что можно двигать,
менять и исследовать и чему каждое действие учит. Не ограничивайся статичной презентацией без обоснования.

## Уточнение команд и расширений (2026-10-28)

Этот раздел заменяет прежние описания автоматического обновления main и сборки всех тем при check/publish.
check собирает только выбранную тему, обновляет оба постера при изменении HTML или самих изображений,
проверяет карточку и запускает тесты. Он не делает fetch/merge и не устанавливает зависимости.
Обновление репозиториев (git pull --ff-only), установка зависимостей (npm ci) и сборка всех тем
(npm run build -- --all) выполняются явно и отдельно. Публикация берёт только HTML, карточку, тест,
два постера и файл их контрольных сумм выбранной темы. Чужие изменения и непустой индекс блокируют
публикацию; общие документы и изменения ядра отправляются отдельным PR.

Форматы печати объявляются в TOPIC_SHEETS: ключ — kind, значение — объект
{ label, about, generate(num), sheet(variant, space), key(variants), two, previewKey, pageClass }.
Ядро само создаёт кнопки, сохраняет выбор, показывает ключ и раскладывает листы. Подмена drawSheets
и изменение меню из helpInit запрещены. См. тему треугольников как пример.

Для следующей версии объяви TOPIC_PRINT_VERSIONS: { 1: { word: oldWord, ... }, 2: { word: newWord, ... } }.
В каждой версии перечисли все доступные форматы. Генератор возвращает модель со своим label.
Сохрани старые генераторы вместе с используемыми ими типами, ответами и константами: замыкание старого
генератора на изменённый TYPES не сохраняет совместимость. Для старого зерна используй taskRnd(n, i, 1).
Интерфейс принимает номера с версией, например 1-4817, и не заменяет её текущей при сохранении.
При изменении структуры модели обеспечь совместимый sheet/key или отдельную обработку старой модели.
Старые снимки не перезаписывай: сохраняй отдельным файлом версии и проверяй через printVariant(n, kind, version).
Снимки дополнительных форматов содержат модель листа и ключ; добавление формата требует его снимка.
