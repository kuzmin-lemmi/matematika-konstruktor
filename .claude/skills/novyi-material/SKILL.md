# Новый материал в конструкторе «Матшага»

Конструктор облегчает ИИ создание материалов: используй ядро, контракт темы и ближайший готовый пример,
чтобы сосредоточиться на математике и методике. Конструктор: `D:\Конструктор математика`.
Папка сайта определяется через `tools/paths.mjs` (на этом компьютере `C:/Users/admin/Desktop/matematika`;
если работаешь в worktree сайта — передавай `--site <папка worktree>`).
Пиши по-русски: ответы, комментарии, тексты интерфейса, коммиты.

## 0. Прочитай перед работой

1. `AGENTS.md` конструктора — общие правила, подготовка двух репозиториев и обязательная живая доска.
   `ИНСТРУКЦИЯ.md` — контракт темы (раздел 3), команды (7), расширения и ограничения версий (9).
2. Сайт: `AGENTS.md` (разделы 4, 5, 7, 8, 9), `docs/FORMATS.md`, `docs/TECH.md`,
   `docs/MATERIALS.md` — банк идей и **типичные ошибки учеников по теме** (из них строятся ловушки).
3. Выбери образец по задаче: `materials/arifmeticheskii-kvadratnyi-koren/` — числа и ОГЭ;
   `materials/formuly-sokrashchennogo-umnozheniya/` — выражения;
   `materials/priznaki-ravenstva-treugolnikov/` — ввод доказательства и дополнительные листы.
   Живая доска — API ядра (`LIVE`, `step.live`, `liveTo`) и чертёжные помощники `GEO`: ИНСТРУКЦИЯ.md, раздел 9,
   рабочий пример — доска заготовки. Методический образец взаимодействий — `public/materials/ugly-pri-parallelnyh-pryamyh.html` сайта.

Проверь `git status -sb` в обеих папках. Обновление Git и `npm ci` выполняются явно, отдельно от `check`.
Готовность `gh` проверяй перед публикацией; наличие подключённого GitHub не означает авторизацию CLI.

Не выдумывай номера параграфов и страницы учебника: в карточке — только название главы, в ответе скажи об этом.
Содержание учебника по главам сверяй у автора, если сомневаешься в объёме темы.

## 1. Заготовка

```bash
cd "D:\Конструктор математика"
npm run new -- <slug> --title "Название темы" [--site <папка сайта>]
```

slug — транслит латиницей через дефис; после публикации не меняется. Команда создаёт и собирает
рабочий пример, но сама тесты не запускает. Дальше заменяй пример содержанием, собирай и проверяй.

## 2. Спроектируй до кода

- Перечисли содержательные взаимодействия и математический смысл каждого; реализуй полезные,
  объясни исключённые. Полные требования к движению, сбросу, управлению и проверке — в разделе
  «Живая интерактивная доска» `AGENTS.md`. Пошаговый показ и «Другие числа» сами по себе их не заменяют.
- **Доска** — 8–12 шагов «вопрос классу → показ». Главная картинка темы (SVG, viewBox 980 × 400), шаг-ловушка
  на самой частой ошибке, шаг «а если условие нарушить», в конце — правило. `note` — что сказать словами.
  «Другие числа» (`boardExample(true, old)`) — тот же показ с новыми удобными числами.
- **Живая модель** — одна `const LIVE` на доску: `model(e)`, `fix` (прилипание, границы), `ok` (вырожденные
  случаи — `GEO.fine` для фигур). На шагах `live`: `handles` (что тянуть), `controls` (ползунок, переключатель,
  выбор, кнопка), `enter` (положение при входе), `reveal` (опыт через `liveTo`). Мышь, касание, клавиатура,
  сброс, повтор и reduced-motion уже в ядре — не пиши их в теме. Чертёж — `GEO`: вершины, стороны,
  углы, штрихи, дужки, подписи наружу от фигуры.
- **Типы заданий** — 4–10. Генерация из зерна, отсев вырожденных случаев в `bad`: одинаковые варианты,
  ответ виден без вычислений, «случайно» целый ответ, где тренируется дробный.
- **Ошибки** — каждая объясняется с вычислением, типичная называется по имени («Ты сложил числители
  и знаменатели…»). Коды ошибок — в `CATS`.
- **Ловушки раздатки** (`traps`) — ответы, которые получаются при типичных ошибках, а не случайные числа.
- **Тренажёр** — 2–4 раздела по сложности или по видам заданий.
- **Раздатка** — 6–8 заданий, ответы в варианте различны; задание с выбором (2–3 ответа) — одно на вариант.
- **Бланк ОГЭ** (8–9 класс) — свои задания (`OGE_V1`, `ogeTask`) с ответом-числом: «в ответ запишите больший
  корень», «номер наибольшего числа». Ответ — строка вида `−0,5`, до 10 символов.

## 3. Наполни тему

`material.json` (тексты), `topic.js` (содержание), `help.html` (справка), при нужде `topic.css`.
Запись — функциями ядра: дробь `F`, смешанное число `M`, корень `RT` (дробь под корнем — `RT(..., true)`),
`htmlQ`/`keyQ`/`decStr` для чисел, `MINUS` (U+2212) для минуса, десятичная запятая. Точная арифметика —
дроби `Q` (никаких 0.1 + 0.2). Никакого `Math.random()` в `gen` — только `rnd` из аргумента.

```bash
npm run build -- <slug> [--site <папка сайта>]
npm test
```

## 4. Проверь глазами

- Доска: все шаги, обе темы (светлая и тёмная), элементы не выходят за viewBox, подписи не налезают.
  Живые шаги: протяни каждую ручку мышью к краям, проверь стрелки, «Сбросить», «▶ Повторить опыт».
- Раздатка: предпросмотр печати / PDF — лист A4 с сеткой, без сетки, **два варианта на листе** (низ не обрезан),
  ключ; бланк ОГЭ — клеточки и образец.
- Тренажёр на ширине телефона (390 px): поля ввода, кнопки, длинные формулы не рвутся.
- Снимки можно делать безголовым Chrome через CDP (как `scripts/capture-posters.mjs` сайта), если окно
  встроенного браузера не отрисовывается.

## 5. Сайтовая часть, показ, одобрение, публикация

Файлы сайта лежат в выбранной папке сайта; `npm run new` уже создал их черновики.

1. `tests/<slug>.test.mjs` — **независимое решение** каждого типа (ответ считает тест, не код материала):
   генератор, ключ 30 вариантов, тренажёр принимает независимый ответ, типичные ошибки называются.
   Для бланка ОГЭ — отдельная функция ответа.
2. Карточка `src/content/items/<slug>.md`: `access: free`, `added` (дата публикации), `poster: posts/<slug>.jpg`,
   `order` по классу, описание по абзацу на режим, `sheets: - { kind: oge, label: "Бланк ОГЭ" }` если есть бланк.
   Если в тот же день уже добавлен другой материал — `featured: true`, иначе в блоке «Новое» останется он.
3. `docs/ROADMAP.md` сайта — отметь фактически выполненную работу с датой; решение автора — в журнал
   `docs/STRATEGY.md`. Документы отправляются отдельным PR: незакоммиченные общие файлы блокируют `publish`.
4. **`npm run check -- <slug>`** — сборка только выбранной темы, обновление двух постеров и `.source.json`
   при изменении HTML или изображений, карточка, тест-контракт, `npm run validate` сайта.
   Git и зависимости не обновляет. Пока есть «✗» — исправляй.
5. **`npm run show -- <slug>`** — открыть материал автору. Напиши коротко: что на доске, в раздатке (все виды листа),
   в тренажёре, что посмотреть руками (печать, телефон). **Спроси, публиковать ли.**
6. Публикуй **только после явного одобрения автора в чате** на этот материал («одобряю», «публикуй»,
   «отправляй на сайт»). Отдельно подготовь актуальный `main` сайта с пустым индексом и изменениями только темы.
   **`npm run publish -- <slug> --approved`**: сборка выбранной темы, проверки, ветка, коммит, PR,
   слияние, синхронизация `main`, GitHub Pages, проверка matshag.ru, первый снимок при его отсутствии.
   Исходники и снимок конструктора отправь отдельным `git push`. Сообщи автору ссылку из итога.

Не публикуй вручную (git/gh в обход команды) и не ослабляй проверки, чтобы команда прошла.
Правки ядра и кода сайта — обычным PR в репозиторий сайта: `publish` коммитит только материалы.

## 6. Ловушки, на которые уже наступали

- **NaN/undefined в ключе или таблице букв** — у типа с нечисловым ответом (`est`, `choice`, `eq`) нет своего
  `keyHTML`/`key`. Тест-контракт ловит, но лучше сразу задать.
- **Обрезанный лист** при «два варианта на листе» — длинная инструкция или много ловушек; проверяй PDF.
- **Чертёж за краем** — координаты считай от viewBox 980 × 400 (так обрезалась прямая y = −9 на параболе).
- **Вёрстка рассыпается** в `.inrow` и карточках разделов (flex): несколько инлайн-кусков (`<i>x</i><sub>1</sub> =`)
  оборачивай в `<span class="nw">`.
- **Перенос посреди формулы** — `<span class="nw">…</span>` вокруг «x = ±√14», выражения с коэффициентом.
- **Минус дефисом** — в подписях SVG тоже нужен `MINUS`.
- **Сравнение в тестах jsdom** — массивы и объекты из окна материала — другой «мир» JS: сравнивай
  `[...arr]` или через `JSON.parse(JSON.stringify(x))`.
- **Совпадение заданий** бланка и кодового слова с одним номером возможно для небольших генераторов — это не ошибка.
- **Скрытая раздатка** — второй вид листа должен быть виден: в материале (кнопки на стартовом экране, переключатель)
  и на сайте (поле `sheets` карточки).
- **Имена в теме совпали с ядром** — тема и ядро в одном `<script>`: `const pt` в теме и в ядре дадут SyntaxError.
  Поэтому геометрия ядра лежит в `GEO.*`, а функции живой доски называются `live*`. Не объявляй в теме `GEO`,
  `LIVE` для других целей, `LV`, `B`, `BW`, `BH`.
- **Ручка закрывает подпись** — в вершине с ручкой подпись ставь через `GEO.vertex` (отступ 46) или дальше.
- **Изменились варианты опубликованной темы** — тест снимка упадёт. Не обновляй снимок, чтобы «починить тест»:
  либо верни генератор, либо подними `GEN_VERSION` по правилам `ИНСТРУКЦИЯ.md`.

## 7. Ядро

Правка `core/` касается всех тем: после неё `npm run build -- --all`, `npm test`, тесты сайта, проверка печати
и доски хотя бы у одной темы. Новая общая возможность (вид ввода, вид листа, помощник чертежа) — в ядро,
тематическое — в тему.

## 8. Расширения и совместимость

Форматы листов объявляй через TOPIC_SHEETS, поля ответа — TOPIC_INPUTS. Схемы и пример —
в ИНСТРУКЦИЯ.md, разделы 3 и 9. Не подменяй drawSheets и не добавляй меню печати через helpInit.

Новая версия требует сохранённых старых типов, генераторов, констант и совместимых sheet/key.
Текущая команда snapshot перезаписывает единственный снимок, а тест пока не обходит снимки версий.
Не обновляй старое ожидание ради зелёного теста. До выпуска версии 2 сначала обеспечь проверку
старых и новых номеров всех форматов; техническая задача описана в этапе 2 ПЛАН-ДОРАБОТКИ.md.
