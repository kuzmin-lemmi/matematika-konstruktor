# План: учитель правит урок сам

Дата: 9 ноября 2026 года. Статус: предложение автора, разработка начинается.

## Зачем

Учитель открывает материал «Матшага» на доске и видит неудачную формулировку. Сейчас исправить её
может только ИИ через конструктор с последующей публикацией. Цель — дать учителю прямо в материале:

1. поправить слова на слайде доски;
2. добавить свой слайд в урок;
3. собрать свой живой чертёж для геометрии.

Правки учителя не должны ломать математику, раздатку, ключи и снимки вариантов.

## Границы и решения, которые нужно принять

- В `AGENTS.md` записано: «Учительский визуальный редактор… не являются целью конструктора». Этот план —
  решение автора развивать такую возможность. **Первым коммитом разработки** обнови `AGENTS.md`
  (раздел «Что это») и `ПЛАН-ДОРАБОТКИ.md` (раздел «Идеи для сайта»): редактор — возможность ядра,
  которая не должна мешать главной цели, то есть работе ИИ с темами.
- Сервера нет. Правки хранятся у учителя: в браузере, в файле комплекта и в ссылке. Учётные записи,
  облачное хранение и сторонние сервисы (GeoGebra) — только отдельным решением автора.
- Редактор меняет **только показ на доске**: `q`, `a`, `note`, `rec` и добавленные слайды. Раздатка, тренажёр,
  ключи, `TYPES`, `GEN_VERSION` и снимки не затрагиваются. Тест снимков должен проходить без изменений.
- Формулы, числа и чертёж темы учитель не правит. Защищённые фрагменты переносятся в правку как есть.
- Изменённое учителем помечено на экране, его можно вернуть «как было» для одного поля, слайда или урока целиком.

## Как устроена доска сейчас (опорные точки в коде)

- `core/board.js`: состояние `B` (`e`, `m`, `steps`, `i`, `phase`). `buildSteps(e)` темы возвращает шаги
  `{ q, a, note, draw(phase, m), rec(phase, m), live }`. Поля могут быть строками или функциями модели (`stepVal`).
  `renderBoard()` выводит их в `#bQ`, `#bA`, `#bRec`, `#bNote`, `#bStage`.
- `core/live.js`: модель `LIVE`, ручки, панель, сброс, повтор, клавиатура, касание, reduced-motion.
- `core/geom.js`: `GEO` — вычисления (`cross`, `lineCircle`, `circles`, `project`, `reflect`…) и рисунок SVG.
- `core/shell.js`: `store.get/set` — localStorage с префиксом `matshag:<slug>:`.
- Формулы в тексте — элементы (`F` → `span.frac`, `RT` → `span.rt`, `X` → `<i>`), числа — обычный текст.

## Этап 1. Правка слов на слайде

**Что видит учитель.** Кнопка «✎ Править» на доске (рядом с «💬 Учителю»). В режиме правки поля вопроса,
ответа, записи в тетради и подсказки учителю становятся редактируемыми. Формулы и числа подсвечены и не
редактируются. Кнопки «Готово», «Вернуть как было». Изменённое поле отмечено значком ✎ и в обычном режиме.

**Привязка правки к полю.** Ключ — `шаг:поле`, например `3:a` или `3:rec:1`, плюс `fp` — отпечаток
исходного текста без чисел (хэш строки после замены защищённых фрагментов на `{}`). Номер шага берётся
из порядка `buildSteps`. Если тема поменяла шаги и `fp` не совпал, правка не применяется, а в списке
правок помечается «устарела — тема изменилась» с исходным и новым текстом.

**Защищённые фрагменты.** При входе в правку HTML поля разбивается на текст и фрагменты: любой элемент
(`span`, `i`, `b`, `sup`…) и любая группа цифр. Фрагменты отображаются с `contenteditable="false"`.
В правке хранится шаблон, например `"Угол равен {0}: это {1} суммы дуг"`. При показе шаблон
заполняется **текущими** фрагментами поля. Поэтому правка переживает «Другие числа» и движение
живой модели. Если число фрагментов изменилось, правка не применяется (как «устарела»).

**Где в коде.**
- Новый файл `core/edit.js`: режим правки, разбор на фрагменты, применение шаблона, список правок.
- `renderBoard()` перед выводом прогоняет каждое поле через `editApply(ключ, html)`.
- Санитайзер: в шаблоне допускаются только текст, `<b>`, `<i>`, `<br>`. Всё остальное удаляется, вставка — как простой текст.
- Тест-контракт: для каждой темы правка поля шага 1 применяется, переживает `boardNumbers(true)`, снимается «Вернуть».

**Готово, когда:** на «Углах между хордами и секущими» и на теореме Пифагора правка слова сохраняется
после перезагрузки страницы, переживает «Другие числа» и движение ручек, раздатка и снимки не изменились.

## Этап 2. Комплект урока: файл и ссылка

**Формат комплекта** (один JSON на тему):

```json
{
  "matshag": 1,
  "slug": "ugly-mezhdu-hordami-i-sekushchimi",
  "title": "Мой урок, 7Б",
  "edits": { "3:a": { "fp": "a1b2c3", "t": "Угол равен {0}…" } },
  "slides": [],
  "drawings": []
}
```

- Хранится в `store` под ключом `kit`. Можно держать несколько комплектов: «7А», «7Б».
- «Сохранить файлом» — скачивание `<slug>-урок.json`; «Открыть файл» — загрузка с проверкой `slug` и схемы.
- «Ссылка на урок»: комплект сжимается (`CompressionStream('deflate-raw')`) и кладётся в `#kit=…` (base64url).
  Хэш не уходит на сервер. Если ссылка длиннее примерно 8000 символов — предложить файл.
- Открытие по ссылке спрашивает: «Применить правки учителя?», не перезаписывая свой комплект молча.

**Готово, когда:** комплект, переданный ссылкой на другой компьютер, даёт тот же урок; битый или чужой
комплект отклоняется с понятным сообщением.

## Этап 3. Свой слайд

- «＋ Слайд после этого». Слайд: вопрос, ответ, запись в тетради, подсказка учителю, и одно из:
  без чертежа, картинка (data-URL, ограничение размера ~300 КБ), чертёж текущего шага (копия `draw`
  на момент вставки) или свой чертёж из этапа 4.
- Формулы — простая запись с предпросмотром: `a^2`, `x_1`, `sqrt(…)`, `(a)/(b)`, `*` → «·», `-` → «−».
  Разбор в `core/edit.js`, вывод через уже существующие `F`, `RT`, `X`, `MINUS`.
- В `B.steps` слайд учителя вставляется после шага-якоря с ключом `fp` якоря. Не нашёл якорь — в конец, с пометкой.
- Слайды учителя видны в счётчике шагов и в превью, их можно переставлять и удалять.

**Готово, когда:** добавленный слайд с формулой и картинкой показывается на месте после перезагрузки
и по ссылке, «Вернуть как было» убирает его.

## Этап 4. Живые чертежи учителя

Делается в два уровня; второй — только если первый окажется мал учителям.

### 4а. Чертёж из готовых моделей тем

Учитель берёт модель, уже написанную ИИ в теме, и настраивает её показ, не трогая математику:
какие ручки доступны, какие подписи, величины углов и длины показаны, что подсвечено,
какой опыт запускает «▶ Повторить».

- Тема объявляет необязательный реестр `TOPIC_MODELS = { имя: { title, model, draw, handles, parts } }`,
  где `parts` — список включаемых элементов (`{ id, label, default }`). Первый образец — тема с живой
  доской из `materials/`, например «Углы между хордами и секущими» (точки на окружности, дуги, угол).
  Углы при параллельных прямых пока есть только на сайте; их модель подойдёт после переноса на конструктор.
- Ядро даёт окно настройки: флажки `parts`, ручки, начальное положение (перетащить и «Запомнить»).
  Сохраняется в `drawings` комплекта как `{ model, parts, state }`.
- Управление, сброс, повтор, клавиатура и касание — из `core/live.js`, без своего кода.

### 4б. Свой построитель (мини-геометрия)

Инструменты: свободная точка, точка на отрезке или окружности, отрезок, луч, прямая, окружность
(центр и точка, центр и радиус), пересечение, середина, перпендикуляр, параллель, биссектриса,
угол (дуга и величина), длина, подпись, скрыть/показать, цвет из классов `g-*`.

- Новый файл `core/construct.js`. Чертёж — список объектов с зависимостями:
  `{ id: 'C', type: 'cross', of: ['a', 'b'] }`. Пересчёт по порядку списка через функции `GEO`.
- Свободные точки — ручки `LIVE`; рисунок — функции `GEO`. Своего обработчика перетаскивания не писать.
- Вырожденные случаи: нет пересечения, совпали точки, окружность нулевого радиуса — объект и зависимые
  от него прячутся, ручка не уходит за рамку 980 × 400 (`GEO.keepIn`).
- Отмена и повтор действия, удаление с зависимыми (с предупреждением), привязка к сетке.
- Чертёж сохраняется в `drawings` и может стоять на слайде учителя.
- Тест: случайные построения из всех инструментов, ручки в крайние положения — все координаты конечны,
  ничего не падает; сохранение и загрузка дают тот же SVG.

**Готово, когда:** учитель за 5 минут собирает «две параллельные прямые и секущая» с подписанными углами,
двигает секущую мышью, пальцем и стрелками, и это работает по ссылке на другом компьютере.

## Этап 5. Удачная правка — для всех

- В списке правок кнопка «Предложить для всех»: формирует файл или текст с темой, ключами,
  исходными и новыми формулировками.
- ИИ переносит принятые формулировки в тему (`buildSteps`), прогоняет `npm run check`, автор одобряет
  публикацию обычным порядком из `AGENTS.md`. Канал доставки (почта, форма, issue на GitHub) — решение автора.

## Порядок и проверки

| Этап | Что | Объём | Зависит от |
|---|---|---|---|
| 0 | Обновить `AGENTS.md` и `ПЛАН-ДОРАБОТКИ.md` | маленький | — |
| 1 | Правка слов | средний | 0 |
| 2 | Комплект: файл и ссылка | маленький | 1 |
| 3 | Свой слайд | средний | 2 |
| 4а | Чертёж из моделей тем | средний | 2 |
| 4б | Свой построитель | большой | 4а и отзывы учителей |
| 5 | Предложить правку для всех | маленький | 2 |

Пилот: этапы 1–2 на одной теме, показать 1–3 учителям, по их отзывам решать про 3 и 4.

На каждом этапе: изменения в ядре → `npm run build -- --all`, `npm test`, `npm run check -- <slug>`
хотя бы для одной темы; собранные HTML уходят на сайт обычным PR, как любая правка ядра.
Проверить: проектор (крупный шрифт), телефон, тёмная тема, касание, клавиатура, reduced-motion, печать
(режим правки и значки ✎ не печатаются).

## Риски

- **Учитель внесёт математическую ошибку в текст.** Числа и формулы защищены, правка помечена значком,
  есть «Вернуть как было». Ответственность за свои слова — на учителе; сайт показывает исходный текст по умолчанию.
- **Тема обновилась, правки «поехали».** Отпечаток `fp` и проверка числа фрагментов: устаревшая правка не
  применяется, а показывается в списке.
- **Потеря правок при очистке браузера.** Напоминание сохранить файлом, когда правок больше нескольких.
- **XSS через комплект по ссылке.** Санитайзер шаблонов, картинки только `data:image/(png|jpeg|webp)`,
  объекты чертежа — только известные типы и числа.
- **Рост размера HTML материала.** Редактор и построитель грузить одним блоком ядра; следить за размером
  собранного файла, 4б при необходимости вынести в общий файл сайта.
