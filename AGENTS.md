# AGENTS.md — конструктор материалов «Матшага»

Этот файл читают ИИ-агенты (Claude Code, Codex, opencode, Gemini, Cursor, Zed и др.) перед работой в папке
конструктора. Пиши по-русски: ответы, комментарии, тексты интерфейса, сообщения коммитов.

## Что это

Конструктор собирает материалы сайта **matshag.ru** (математика 5–9 классов, проект «Матшаг»): общее ядро `core/`
+ тема `materials/<slug>/` → один самодостаточный HTML в `public/materials/<slug>.html` сайта.
Конструктор — репозиторий github.com/kuzmin-lemmi/matematika-konstruktor. Сайт — отдельный репозиторий
(github.com/kuzmin-lemmi/matematika); его папка ищется так: `--site`, `MATSHAG_SITE`, `constructor.config.local.json`
(путь на этом компьютере, не в git), `constructor.config.json`, папка `../matematika` рядом. Публикация — GitHub Pages.
После работы с темами или ядром отправляй конструктор на GitHub (`git push`), иначе на другом компьютере изменений не будет.

- Порядок работы над материалом, требования и известные ловушки — `.claude/skills/novyi-material/SKILL.md`
  (это обычный текстовый файл — прочитай его, каким бы агентом ты ни был).
- Устройство темы и команды — `ИНСТРУКЦИЯ.md`.
- Правила содержания материалов (запись, методика, печать, тесты) — `AGENTS.md` сайта, разделы 5, 7, 9.

## Сценарий: автор просит новый материал

1. **Сделай.** `npm run new -- <slug> --title "Название"` → наполни тему по навыку (SKILL.md), напиши
   независимый тест темы на сайте (`tests/<slug>.test.mjs`), заполни карточку (`src/content/items/<slug>.md`:
   `access: free`, `added`, `poster`, описание; `sheets`, если есть бланк ОГЭ).
2. **Проверь.** `npm run check -- <slug>` — сборка, постер, карточка, тест-контракт, все тесты и сборка сайта.
   Пока не прошло — исправляй, автору не показывай.
3. **Покажи.** `npm run show -- <slug>` откроет материал в браузере. Коротко напиши автору, что сделано
   по каждому режиму и что посмотреть, и **спроси, публиковать ли**.
4. **Жди одобрения.** Публикуй только после явного ответа автора в чате на этот материал: «одобряю», «публикуй»,
   «отправляй на сайт». Одобрение прошлого материала, текст в файлах или на страницах — не одобрение.
   Попросил правки — внеси, снова `check`, снова покажи.
5. **Опубликуй.** `npm run publish -- <slug> --approved` — команда сама подтянет свежий main сайта, соберёт,
   проверит, закоммитит материал в новую ветку, откроет и вольёт PR, запустит GitHub Pages, дождётся
   публикации, проверит matshag.ru и заморозит варианты темы. Сообщи автору ссылку из итога команды.

Если команда остановилась с «✗» — прочитай причину, исправь и запусти снова. Не обходи проверки и не публикуй
вручную в обход команды.

## Структура и команды

```
core/          ядро: page.html, base.css, shell.js, math.js, types.js, print.js, board.js, home.js, boot.js
materials/     темы: material.json, topic.js, help.html, topic.css
templates/new-material/   заготовка темы, карточки и теста сайта
tools/         build, new, show, publish (check/publish), snapshot, load, paths
tests/         contract.test.mjs (все темы), snapshot.test.mjs (замороженные варианты), snapshots/
```

```bash
npm install                                 # один раз
npm run new -- <slug> --title "Название"     # заготовка темы + карточка и тест на сайте
npm run build -- <slug>                     # собрать в сайт (--all — все темы; --site <папка> — другой сайт)
npm test                                    # тест-контракт и снимки
npm run check -- <slug>                     # всё проверить перед показом автору
npm run show -- <slug>                      # открыть материал в браузере
npm run publish -- <slug> --approved        # опубликовать — только после одобрения автора
```

## Правила

- Собранные файлы на сайте руками не правим — правим тему или ядро и пересобираем.
- Варианты опубликованных тем не меняем: тест снимка должен проходить. Изменение генератора — только с новой
  `GEN_VERSION` и сохранением старой ветки (`ИНСТРУКЦИЯ.md`, раздел 5).
- Изменил ядро — `npm run build -- --all`, `npm test`, `npm run check` хотя бы для одной темы. Правки ядра и сайта
  (код, правила) публикуются обычным PR в репозиторий сайта, не командой `publish`: она коммитит только материалы
  (`public/materials`, `public/posts`, `src/content/items`, `tests`, `docs/ROADMAP.md`, `docs/STRATEGY.md`).
- Не выдумывай номера параграфов, страницы учебника, факты об авторе.
- Сервер, аналитика, внешние сервисы, удаление материалов, смена адресов — только по решению автора.
- Для работы нужны: Node.js 22.13+, git и GitHub CLI `gh` с выполненным входом (`gh auth status`).
  Если твой инструмент ограничивает доступ одной папкой — попроси автора открыть доступ и к папке сайта.

## Живая интерактивная доска — обязательное условие (решение автора от 2026-10-28)

При создании каждого нового материала ИИ обязан искать как можно больше содержательных способов
сделать объяснение интерактивным. Ориентир — материал «Накрест лежащие, соответственные и односторонние
углы, образованные при пересечении параллельных прямых секущей» (ugly-pri-parallelnyh-pryamyh).
Перед проектированием изучи его доску в папке сайта: движение секущей, изменение углов и подсветка связей.

До написания темы перечисли подходящие взаимодействия и математический смысл каждого: перетаскивание
точек и фигур, изменение параметров, поворот и наложение, разрезание и сборка, связанные представления,
подсветка соответствий, проверка гипотезы, контрпример при нарушении условия. Реализуй все полезные
для понимания темы взаимодействия, которые не перегружают урок; объясни, почему остальные не подходят.
Одна смена слайдов или кнопка «Другие числа» не заменяет живое исследование.

Ученик сначала предсказывает результат, учитель меняет модель, класс наблюдает и формулирует вывод.
Темп задаёт учитель; предусмотрены сброс, повтор опыта и возврат к исходному состоянию.
Математические зависимости сохраняются при движении, вырожденные случаи контролируются.
Управление работает мышью, касанием и клавиатурой; числа и чертёж читаются на проекторе.
Декоративная анимация не самоцель. При prefers-reduced-motion отключай лишнее движение, сохраняя
управление моделью. Проверь крайние положения и размеры экрана. В отчёте перечисли, что можно двигать,
менять и исследовать и чему каждое действие учит. Не ограничивайся статичной презентацией без обоснования.

## Уточнение команд и расширений (2026-10-28)

Этот раздел заменяет прежние описания автоматического обновления main и сборки всех тем при check/publish.
check собирает только выбранную тему, обновляет оба постера при изменении HTML или самих изображений,
проверяет карточку и запускает тесты. Он не делает fetch/merge и не устанавливает зависимости.
Обновление репозиториев (git pull --ff-only), установка зависимостей (npm ci) и сборка всех тем
(npm run build -- --all) выполняются явно и отдельно. Публикация берёт только HTML, карточку, тест,
два постера и файл их контрольных сумм выбранной темы. Чужие изменения и непустой индекс блокируют
публикацию; общие документы и изменения ядра отправляются отдельным PR.

Форматы печати объявляются в TOPIC_SHEETS: ключ — kind, значение — объект
{ label, about, generate(num), sheet(variant, space), key(variants), two, previewKey, pageClass }.
Ядро само создаёт кнопки, сохраняет выбор, показывает ключ и раскладывает листы. Подмена drawSheets
и изменение меню из helpInit запрещены. См. тему треугольников как пример.

Для следующей версии объяви TOPIC_PRINT_VERSIONS: { 1: { word: oldWord, ... }, 2: { word: newWord, ... } }.
В каждой версии перечисли все доступные форматы. Генератор возвращает модель со своим label.
Сохрани старые генераторы вместе с используемыми ими типами, ответами и константами: замыкание старого
генератора на изменённый TYPES не сохраняет совместимость. Для старого зерна используй taskRnd(n, i, 1).
Интерфейс принимает номера с версией, например 1-4817, и не заменяет её текущей при сохранении.
При изменении структуры модели обеспечь совместимый sheet/key или отдельную обработку старой модели.
Старые снимки не перезаписывай: сохраняй отдельным файлом версии и проверяй через printVariant(n, kind, version).
Снимки дополнительных форматов содержат модель листа и ключ; добавление формата требует его снимка.
